# PassGame

PassGame evaluates whether language models preserve accumulated constraints while
updating a string. Each turn introduces one new rule. The model generates the
next password, and the game ends at the first failed response. The study compares
four rule orders for 24 development games across 19 model conditions.

## Setup

Use Python 3.11+, Git, and [uv](https://docs.astral.sh/uv/getting-started/installation/).
Run commands from the repository root:

```sh
uv sync --locked
```

For pip, create a Python 3.11+ virtual environment, activate it, then run:

```sh
python -m pip install --require-hashes -r requirements.txt
python -m pip install --no-deps -e .
```

## Run through an API

The API configurations use the Tübingen ML Cloud endpoint. Set your API key and
check the selected configuration's model access, token prices, and spending ceiling.
Then run:

```sh
export TUEBINGEN_API_KEY="YOUR_API_KEY"
uv run --locked python -m passgame.run --config configs/api/qwen3.6-35b-a3b-nonthinking-16k.yaml --preflight
uv run --locked python -m passgame.run --config configs/api/qwen3.6-35b-a3b-nonthinking-16k.yaml
```

For another compatible API, copy a configuration and edit its endpoint, model ID,
credential environment-variable name, prices, and budget. Use a fresh output
directory. Preflight checks settings without sending model requests.

## Run on a cluster

Obtain the model weights and vLLM container, then submit the serving/evaluation
script to a GPU allocation:

```sh
mkdir -p scripts/local logs
cp scripts/cluster/slurm.example.sbatch scripts/local/evaluate.sbatch
```

Set your scheduler partition/account, model and image paths, served model name,
and configuration in the copied script. Submit from the repository root:

```sh
sbatch scripts/local/evaluate.sbatch
```

The script starts vLLM, waits for readiness, evaluates the model, and stops the
server. The [reproducibility guide](docs/reproducibility.md) gives model-download,
container, GPU, API, and source-snapshot instructions.

## Results and analysis

Each evaluation writes responses, provenance, completion accounting, CSV summaries,
and paired bootstrap estimates to its configured `output_dir` under `outputs/`.
For example:

```sh
uv run --locked python -m passgame.analyze outputs/qwen3.6-35b-a3b-nonthinking-16k/records.jsonl \
  --output outputs/analysis --repetitions 2000 --seed 20261008
```

Submitted responses and analyses are in [results/](results/README.md). The reported
study contains 1,824 conversations and 10,919 attempted responses. Model failures
are observed outcomes; unrequested later turns are not fabricated responses.
